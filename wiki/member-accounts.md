# Member accounts (shop login, History, Analytics)
- 2026-10-23: Petch asked for optional shop accounts: Guest (no login, menu as today) vs Member (logo + name header, order History, Analytics). Phases: 0 bcrypt spike → 1 data model + test harness → 2 Admin page → 3 Login + branding → 4 History → 5 Analytics. Plan approved 2026-10-23.
- 2026-10-23 decisions (Petch):
  - Guest keeps ordering exactly as today. Shop QR (`?shop=CODE`) stays for ordering only and never opens History/Analytics (a leaked sticker must not leak a shop's spend).
  - Login = phone + password. Admin creates the shop → system makes a random temp password, shown once, stored only as a bcrypt hash, expires in 7 days → first login forces the shop to set its own. Forgot → shop asks us → admin presses reset (new temp password; old one and every logged-in device stop working). No invite QR in v1.
  - Petch first wanted admins to see every password "for simplicity"; dropped after comparing: reset is the same one click, and stored passwords risk reuse (shops' LINE/bank passwords), PDPA, and "who placed this order" disputes.
  - Admin = web page. Claude's proposal: served by Apps Script (HtmlService), Google-account protected, not on the public Pages site. Unverified: whether a plain Gmail (non-Workspace) deployment can allowlist several staff emails — check in Phase 2.
- 2026-10-23 data model (planned, sandbox sheet): Master gets Logo_File_ID / Member_Status; new tabs Member_Auth (Customer_ID, Login_Phone, Password_Hash, Must_Change, Temp_Expires_At, Password_Set_At) and Sessions (token hash, 90 days); Order gets Auth = member / shop_qr / guest; Order_Items gets Category. Shop key = Master.Code (Customer_ID) — config `shop_id` SU22 is the Betagro branch, not a customer. Logos go to Drive, never the public repo.
- 2026-10-23 known limit: Analytics only sees web orders (LINE-chat and counter orders have no items) and shows ordered, not delivered, weight.
- 2026-10-23 Phase 0: vendored bcryptjs 2.4.3 as `backend/apps-script/Bcrypt.gs` (library unchanged; wrapper adds Apps Script randomness and a stub `setTimeout`, which Apps Script lacks and the library reads on load). In Node, simulating Apps Script: OpenBSD test vector PASS; cost 10 = 53 ms, cost 12 = 214 ms. `Spike.gs` (temporary) measures the same inside Apps Script — waiting on Petch's run.
- 2026-10-23 Phase 0 result (Petch ran Spike.gs in Apps Script): cost 10 check 223 ms, 11 = 282 ms, 12 = 469 ms; test vector PASS; HMAC-SHA256 ×1000 = 529 ms (so PBKDF2 here would be far too weak — bcrypt it is). **Chosen: bcrypt cost 12** (~0.5 s, 2× headroom under 1 s). Spike.gs deleted from the repo; Petch to delete it from the Apps Script project, keep Bcrypt.
- 2026-10-23 Phase 1 built (local, NOT deployed / pushed): `setup()` now also adds tabs Member_Auth + Sessions, Order.Auth, Order_Items.Category (also onto the existing Order_Items tab), Master.Logo_File_ID / Member_Status. doPost writes Auth = guest / shop_qr and Category from the SKU prefix. New `backfillCategories()` (run by hand) fills Category on old lines. Old orders keep Auth empty = treated as guest (only test data exists). Test harness `tests/` (node:test + in-memory sheet, Node built-ins only): 16 tests incl. 7 pinning today's guest/shop-QR flow; a deliberate break in the customer lookup was caught. `npm test` added to CI before deploy.
